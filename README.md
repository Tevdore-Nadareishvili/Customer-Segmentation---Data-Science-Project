## 1. Project Overview & Problem Statement

### Problem Statement
Currently, the business treats every customer the same because we lack insights into their buying behavior. Marketing to everyone equally wastes money. The problem is to turn raw transaction data into specific customer groups—like VIPs or those at risk of leaving—so we can target them effectively

### Objectives
Our goal was to transform raw transactional data into actionable business intelligence by:
1.  **Cleaning & Processing:** Handling large-scale transaction logs (>500k rows) to remove noise and errors.
2.  **Feature Engineering:** constructing **RFM (Recency, Frequency, Monetary)** metrics to quantify customer value.
3.  **Segmentation:** Using Unsupervised Learning (**K-Means Clustering**) to scientifically group customers into distinct personas.
4.  **Prediction:** Building Supervised Learning models (**Random Forest & Logistic Regression**) to predict customer segments for future users.

## 2. Dataset & Data Documentation

### Data Source
* **Source:** [UCI Machine Learning Repository - Online Retail II](https://archive.ics.uci.edu/ml/machine-learning-databases/00352/Online%20Retail.xlsx)
* **Description:** This Online Retail II data set contains all the transactions occurring for a UK-based and registered, non-store online retail between 01/12/2009 and 09/12/2011.
* **Initial Size:** 541,909 rows (Raw).
* **Processed Size:** 4,300 unique customers (Aggregated).

### Data Dictionary: Raw Data (`data/raw/online_retail.xlsx`)
| Feature | Description | Data Type |
| :--- | :--- | :--- |
| `InvoiceNo` | A 6-digit integral number uniquely assigning each transaction. If this code starts with the letter 'c', it indicates a cancellation. | String |
| `StockCode` | A 5-digit integral number uniquely assigning each distinct product. | String |
| `Description` | Product (item) name. | String |
| `Quantity` | The quantities of each product (item) per transaction. | Integer |
| `InvoiceDate` | The day and time when each transaction was generated. | Datetime |
| `UnitPrice` | Product price per unit in sterling (£). | Float |
| `CustomerID` | A 5-digit integral number uniquely assigning each customer. | Float |
| `Country` | The name of the country where each customer resides. | String |

### Data Dictionary: Processed Data (`data/processed/rfm_data.csv`)
After cleaning and aggregation, the data is transformed into customer-level metrics:

| Feature | Definition | Derivation Logic |
| :--- | :--- | :--- |
| `Recency` | Days since the customer's last purchase. | `Reference Date - Max(InvoiceDate)` |
| `Frequency` | Total number of unique purchases. | `Count(Unique InvoiceNo)` |
| `Monetary` | Total revenue generated by the customer. | `Sum(Quantity * UnitPrice)` |

### Data Preprocessing Steps
1.  **Cleaning:** Dropped rows with missing `CustomerID`. Removed cancelled transactions (where `InvoiceNo` starts with 'C'). Filtered out negative `Quantity` and `UnitPrice` values.
2.  **Outlier Handling:** Removed extreme outliers (Top 1% of spenders/frequent buyers) to ensure cluster stability.
3.  **Scaling:** Applied Log Transformation (`np.log1p`) to handle skewness in Monetary/Frequency data, followed by `StandardScaler`.

## 4. Results Summary

### Customer Segmentation (Unsupervised Learning)
Using K-Means Clustering (Optimal K=4 determined via Elbow Method), we identified four distinct customer segments:

| Segment Name | Count | Description |
| :--- | :--- | :--- |
| **Champions (VIP)** | 819 | Recent buyers (14 days ago), high frequency (10+ purchases), high spend (~£4,300). |
| **Loyal Customers** | 1,175 | Regular buyers (78 days ago), moderate frequency (3.7), good spend (~£1,500). |
| **Recent Low Spenders** | 823 | Very recent buyers (19 days ago), low frequency (1.9), low spend (~£500). New users. |
| **Lost/Dormant** | 1,483 | Inactive for a long time (~189 days), single purchase history, low spend. |

### Classification Modeling (Supervised Learning)
We trained models to predict these segments based on RFM scores.

* **Best Model:** Random Forest Classifier
* **Accuracy:** 97.21%
* **Key Insight:** The Random Forest model achieved near-perfect precision (99%) for detecting "Champions," ensuring we can accurately target high-value users without false positives.
